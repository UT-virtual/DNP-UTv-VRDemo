# キューブマップ生成に関する実装検討

## 案 A1：パノラマから自動生成キューブマップの実装

### 現状の問題
- 環境パノラマ PNG はシーンの Sky Box に設定されるが、リアルタイムキューブマップの生成には対応していない。
- Reflection Probe による自動ベイク時にキューブマップが生成されるが、シナリオ実行時の環境変更に動的に追従しない。

### 検討の必要な内容

#### 1. 自動生成の方式
- **方式A：Equirectangular → Cubemap 変換（Editor）**
  - `Graphics.ConvertTexture()` を使用して Editor 時にパノラマからキューブマップを生成し、プリセット内に保持。
  - 実装コスト：中程度。複数の面（6枚）をオフスクリーン レンダリングで生成する必要がある。
  - パフォーマンス影響：なし（Editor 時のみ）。

- **方式B：Shader を使用した Equirectangular マッピング**
  - 既存のシェーダーを拡張して、Equirectangular テクスチャから直接キューブマップのような効果を得る。
  - 実装コスト：低程度（既存シェーダーの修正）。
  - 制限事項：Reflection Probe には非対応。リアルタイム環境反射は限定的。

#### 2. ベイクの実装
- `Lightmapping.BakeAsync()` または `Lightmapping.Bake()` でシーン全体を再ベイク。
- Reflection Probe をシーンに配置し、Editor ボタンから手動ベイクを実行。
- 実装コスト：中程度（ベイク管理コードの追加）。
- 実行時間：パノラマサイズ・品質設定によって 10 秒～数分。

#### 3. 解像度・品質の決定
- パノラマ解像度：512×256（現状）
- キューブマップ解像度：256×256（リアルタイム向けバランス）か 512×512（高品質）
- Mip chain：有効にしてリフレクション精度を向上。

### 実装案の推奨順序

1. **優先度 Low**：Equirectangular シェーダー（方式B）の実装
   - 反射表現をリッチにしたい場合のみ。現状の環境パノラマで視覚効果は十分。

2. **優先度 Medium**：Editor での Cubemap 生成ボタン追加（方式A）
   - Build Environment Presets メニューの拡張で実装可能。
   - ベイク時間は許容できる範囲なら後回し可。

3. **優先度 Low**：シナリオ実行時の Reflection Probe 自動更新
   - 実装・テストコストが高く、ビジュアル改善効果が不確定。

### 必要な作業量（概算）

| 項目 | 工数 | 備考 |
|------|------|------|
| Cubemap 生成コード（Editor） | 2h | OffscreenRenderTexture + Graphics.Blit の実装 |
| Reflection Probe ベイク統合 | 1.5h | Lightmapping.BakeAsync の呼び出し管理 |
| テスト（Editor 動作検証） | 1h | 生成品質・実行時間の確認 |
| ドキュメント作成 | 0.5h | ユーザー手順の記述 |
| **合計（実装する場合）** | **5h** | 高品質リアルタイム反射が必須な場合のみ推奨 |

### 推奨事項

**現段階では実装しない。** 以下の理由により。

1. 環境パノラマの視覚効果だけで十分な没入感が得られている（確認済み）。
2. リアルタイム Reflection Probe の更新は実装・性能調査に工数がかかる。
3. #19 では環境切り替えのユーザビリティが主題であり、反射の正確さは副次的。
4. 後段フェーズ（キャラクター・物体モデルの改善）での高優先度が明確になった後に判断すべき。

### 将来の拡張ポイント

- Cubemap 解像度の環境別パラメータ化（Exhibition 低解像度、Temple 高解像度など）。
- Editor での Equirectangular プレビュー機能。
- Cloud Rendering による高品質キューブマップ ベイク（外部サービス利用）。
