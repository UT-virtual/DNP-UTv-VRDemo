## 1. 前提と技術方針

| 項目 | 決定内容 |

| ベース | [BasisVR/basis](https://github.com/BasisVR/basis) の `long-term-support-20260916` ブランチをフォーク（git remote `upstream`） |

| マルチプレイ | LAN・最大2人。**プレイヤーA の Quest が Basis のホストモード（サーバーをプロセス内で起動）**、プレイヤーB がその IP に接続。ポート 4296 |

| 生成AI | 生成・修正の結果は事前に用意した版（モデルとポーズ）で表現する。決まった操作を判定したら、遷移演出とともに次の版へ切り替える |
| 音声指示 | 疑似認識。ボタンを押している間だけマイクを取り込み、音量で発話を確認する。離したら台本の文を認識結果として表示する（§2.4）。音声は相手に送らない |
| 独自コード | `Assets/DNPDemo/` 以下に置く（asmdef：`DNPDemo.Runtime` / `DNPDemo.Editor`） |
| ワールド UI | ワールド空間の uGUI には `BasisGraphicUIRayCaster` を付け、配下のオブジェクトをすべて `UI` レイヤーに置く。Basis は、レーザーが当たったコライダーが `UI` / `OverlayUI` レイヤーにあるときだけ、レーザーとカーソルを描画してボタン操作を通す |
| Basis 本体の改造 | 必要最小限にとどめ、変更箇所はすべて [BASIS_PATCHES.md](BASIS_PATCHES.md) に記録する（upstream をマージするときの衝突対策） |

### 1.1 リモート接続（インターネット越し）に対応する場合のコスト

Basis の通信層（LiteNetLib / UDP）は、もともとインターネット上のサーバーに接続する前提で作られている。そのため、**通信の仕組み自体を新しく作る必要はない**。コストが変わるのは「どこでサーバーを動かすか」と「ホスト＝プレイヤーA という前提をどう扱うか」の2点。

| 方式 | 内容 | クライアントの改修 | 運用・インフラ | 目安 |
|---|---|---|---|---|
| **A. 専用サーバー（推奨）** | クラウドの VPS などで `Basis Server` を動かす（Docker Compose 同梱）。2台ともそのサーバーに接続する | ・接続先アドレスを選ぶ UI<br>・**ロール決定とシナリオの進行管理を「ホスト＝プレイヤーA」から切り離す**（ロビーで役を選ぶ方式、進行管理は Basis の所有権（ownership）で決める） | VPS の構築、UDP 4296 の開放、パスワード設定。少額の月額費用がかかる | 3〜5人日 |
| B. ホストモードのまま | プレイヤーA 側のルーターで UDP 4296 をポート開放し、プレイヤーB がグローバル IP に接続する | 接続先の入力 UI のみ | ホスト側のネットワークにポート開放と固定 IP（または DDNS）が必要。会場の回線やモバイル回線（CGNAT）では使えないことが多い | 0.5人日。ただし接続できる環境が限られる |
| C. NAT 越え／リレー | ポート開放なしで端末同士を直接つなぐ | Basis にはこの仕組みがないので、マッチングとリレーを自作する | リレーサーバーの運用 | 2週間以上 |

- 方式 A のコストの大半は「ホスト＝プレイヤーA」をやめる改修にある。後から対応しやすいように、**ロールの決定とシナリオ進行の権限を判定する処理を1か所（`DemoRoleService`）にまとめ**、ほかのコードは `IsHostMode` を直接参照しないようにする（§2.1）。こうしておけば、リモート対応時に差し替えるのはこのサービスとロビー UI だけで済む。
- 2人で進めるシナリオなので、インターネット越しの遅延（数十〜100ms 程度）による体験への影響は小さい。離れた場所の2人が会話するには、Basis 標準の Opus 通話でボイスチャットを有効にすればよい。その場合、音声指示の取り込み中は相手に送らないよう、音声指示とボイスチャットを切り分ける。

## 2. アーキテクチャ

### 2.1 起動〜接続

1. APK を起動すると `DNPDemo_Main` がワールドとして読み込まれる（Basis の起動処理はシーンに依存しない）。
2. **ロビーパネル**（ワールド空間の uGUI。`BasisGraphicUIRayCaster` で Basis のレーザーから操作する）に「プレイヤーA（ホスト）」「プレイヤーB（参加）」の2つのボタンを出す。
   - A を選ぶと、`DemoSessionService` が人数上限2・デモ用パスワードで `BasisConnectionService.ConnectAsync(entry, name, isHostMode: true)` を呼ぶ。接続できたら UDP ビーコン（`LanHostBeacon`）を1秒ごとにブロードキャストし、パネルに自分の LAN の IP を表示する。
   - B を選ぶと、`LanHostScanner` がビーコンを待ち受ける。ホストが1台だけ見つかれば自動で接続し、複数なら一覧から選ばせる。受信している間は Android の `MulticastLock` を取得する。
   - 予備として、テンキーによる IP の手入力（最後に使った IP を初期値にする）と、Basis 標準の deep link `basisdemo://IP:4296` を使える。
   - 接続の状態は `BasisNetworkConnectionWatchdog.Health` から読み取る。B の再接続は Basis の watchdog に任せる。
3. ロールの決め方：ホスト = プレイヤーA、クライアント = プレイヤーB。決まったロールに応じて `Spawn_PlayerA/B` の位置へ移動する。
   - ロールの判定とシナリオ進行の権限判定は `DemoRoleService` に集約する（`GetLocalRole()` / `GetRole(playerId)` / `HasScenarioAuthority`）。現在の実装では、ホストならプレイヤーA かつ進行の権限あり、と判定する。
   - 各端末は自分のロールを相手に通知し、「プレイヤー ID → ロール」の対応表を持つ。知らない相手から通知を受けたら自分のロールを返信するので、参加の順番によらず両者がそろう。
   - `IsHostMode` を参照するのは `DemoSessionService` と `DemoRoleService` だけにする。

### 2.2 シナリオ進行（中核）

コードは `Scripts/Runtime/Scenario/`、データは `Data/ScenarioData.asset`。

```
ScenarioData (ScriptableObject)   … ステップ定義の配列。シナリオの改訂はこのデータの編集で対応する
   └ ScenarioStep: Id / 運営表示名 / 担当ロール / 完了条件 / タスク文 / キュー列（M2 で操作定義を足す）
ScenarioProgress（純 C#）        … 正となる状態 {seq, ステップ番号}。遷移のたびに seq が変わる
ScenarioDirector (BasisNetworkBehaviour)
   ├ 進行権限を持つ端末（DemoRoleService.HasScenarioAuthority）が状態を持ち、変わるたびに ReliableOrdered で配信する
   ├ 参加・再接続した端末は OnNetworkReady で状態を要求し、権限側が返信する
   └ ほかの端末は「操作完了」と運営操作を権限側へ送るだけ。どちらも seq 付きで、古いステップ宛ては捨てる
StepCompletion（完了条件）
   ├ CuesFinished … 権限側でキューの再生が終わったら進む
   ├ PlayersReady … ロビー。2人目が参加した時点で進む（リセット後に2人ともいる場合は運営が開始する）
   ├ Interaction  … 担当ロールの端末が ScenarioDirector.ReportInteractionComplete() を呼んだら進む（M2 の部品が呼ぶ）
   └ Manual       … 運営の操作でのみ進む（結び）
   運営スキップはどの条件でも常に使える
ScenarioCue（キュー）… LineCue（話者＋字幕＋音声）/ WaitCue / SoundCue / SetObjectActiveCue / BannerCue
   └ 見た目を後に残すキュー（永続キュー）は ApplyInstant を実装する。M3 で版・環境・比較台のキューを同じ形で足す
ScenarioPlayer … ステップに入るたびに、舞台を初期状態に戻し、それまでのステップの永続キューを即時に適用してから、
                 現在のステップのキューを頭から再生する
ScenarioStage  … シーン側の対応表（話者 → 音声と字幕、キー → オブジェクト、効果音、バナー）。SO はシーンを参照できないため
```

- 見た目の状態はすべてステップ番号から決まる。途中参加・運営のジャンプ・通常の進行のどれでも同じ見た目になり、同期は {seq, ステップ番号} だけで済む。途中参加した端末は、現在のステップの台詞を頭から再生する。
- 操作中の途中経過（選択範囲、ストローク、掴んでいる部位の位置）だけは、相手にも見えるよう別途送る（§2.4 の「同期」列）。ステップが進んだ時点で途中経過は破棄し、ステップ番号から決まる状態に戻す。
- 音声クリップが未設定の台詞は、文字数から求めた時間（`LineTiming`）だけ字幕を出す。学者の字幕は頭上（`SubtitleAnchor`）、ナレーターの字幕は視界の下に追従して出す。
- **運営用デバッグ操作**：左右のスティックを同時に2秒押し込むと、運営パネルが目の前に開く（次へ、戻る、最初から）。どちらの端末からでも操作でき、権限のない端末の操作は権限側へ送られる。エディタとデスクトップでは F9 でパネルの開閉、F10 で戻る、F11 で次へ。
- シーンへの配置は、メニュー「DNP Demo/Setup/Install Scenario Into Open Scene」で一度だけ行う（データとプレハブがなければ先に生成する）。以後はシーン・プレハブ・データを直接編集する。

### 2.3 空間ペン

プレイヤーA・B の**右手に1本ずつ常に持たせる**。ペンのモード（選択／ガイド／操作／音声入力）は**現在のステップの操作定義から自動で決まり**、HUD とペン先の表示で示す。体験者にモードを切り替えさせない。

| 要素 | 仕様 |
|---|---|
| 先端スフィア | ペン先に半透明のスフィアを表示する。**右スティックの上下でスフィアの半径を変える**（最小値と最大値を設定）。右スティックの左右は Basis の旋回に使われているので、上下だけを使う |
| ボタン割り当て | トリガー＝選択・描画、グリップ＝掴む、音声入力ボタン＝押している間だけ音声入力（ボタンは実機で Basis 既存の割り当てと競合しないものを選ぶ） |
| 既存機能との競合 | Basis が既に使っているボタン（B/Y＝メニュー、A/X＝ミュートとジャンプ、グリップ＝掴む）は、デモ中は不要な機能を無効化する。ミュートは解除できないようにする。メニューは運営用の操作から開けるようにする |

### 2.4 ペン操作の共通部品

各ステップを個別に実装せず、次の部品の組み合わせで操作を定義する。ステップの操作定義は「部品の種類＋パラメータ（判定ゾーン、目標、制約、台本の文）」として ScenarioData に持たせる。

| 部品 | 操作 | 完了判定 | 同期 |
|---|---|---|---|
| `SelectionTool` | トリガーを押している間、スフィアが通った軌跡を半透明の選択範囲としてマークする。離すと1回分の選択が確定する | 選択範囲が、ステップで指定した部位ゾーン（林檎、左肩〜肘、右手首など）にすべて重なっていれば成功。外れていれば選択範囲を消して、もう一度やってもらう | 確定した選択範囲のサンプル列 |
| `StrokeTool` | トリガーを押している間、空中に線を描く | ガイドモード：始点ゾーンから終点ゾーンまで届いていること。線画：描いた線の外接サイズが一定以上であること | 描画中の点列（間引いて送る）と確定したストローク |
| `ManipulateTool` | 選択した部位をグリップで掴み、ステップごとの制約の範囲で動かす。制約は「平行移動（範囲つき）」または「支点まわりの回転（軸と角度範囲つき）」 | 目標ポーズから許容範囲内で離すと、目標へスナップして完了 | 操作中は制約パラメータを低頻度（約20Hz、Unreliable）で送り、確定時に Reliable で送る |
| `VoiceCommandTool` | 音声入力ボタンを押している間を「音声入力中」として表示する。その間だけ `BasisLocalMicrophoneDriver.AddCaptureHold()` でマイクを取り込み（ミュートのままなので送信はされない）、`averageRms` がしきい値を超えた時間で発話を検知する。離したら `ReleaseCaptureHold()` | ボタンを押している間に一定時間以上の有音があり、ボタンを離した。台本の文を認識結果として表示してから完了とする | 完了イベントのみ |
| `HistoryPanel` | 手元パネルに、これまでに到達した版の一覧を表示する。項目を選ぶと比較台に表示される | ステップで指定した版を選んだ | 選んだ版の ID |

- 部品の内部表現：選択範囲はスフィアのサンプル列（位置＋半径）で記録し、サンプル間隔は半径に比例させる。表示は GPU インスタンシングした半透明スフィア（または生成したチューブメッシュ）。ストロークは点列と LineRenderer（またはチューブメッシュ）。
- 1つのステップで複数の部品を順に使う場合（例：範囲選択 → 音声指示）は、操作定義に部品を順番に並べる。HUD は今どの手順にいるかを示す。

### 2.5 像と版の管理

| 要素 | 内容 |
|---|---|
| `VenusRig` | 共通の胴体に、部位スロット（左腕、右腕、林檎、手鏡）を持つ像。スロットごとにモデルを差し替え、ポーズを適用する |
| `VenusVersion`（ScriptableObject） | 版ごとに、各スロットのモデルとローカルポーズ、表示名（「Ver 1.0」など）を持つ |
| 版の一覧 | 腕なし → Ver 1.0 → Ver 1.1 → Ver 1.2 → Ver 2.0 → Ver 3.0 → Ver 3.1（§3） |
| `ModelTransition` | 版の切り替え演出（ディゾルブ、スキャンライン、パーティクル）。どの版の遷移でも同じ仕組みを使い、変化したスロットだけに演出をかける |
| 比較表示 | 比較台に `VenusRig` をもう1体出し、指定した版を表示する |
| 履歴 | これまでに到達した版はステップ番号から決まる。`HistoryPanel` はこれを一覧表示する |

### 2.6 環境の切り替え

`EnvironmentPreset`（ScriptableObject）に、Skybox（360度パノラマ）、展示室の壁の表示、ライト・アンビエント・リフレクションの設定をまとめて持たせ、クロスフェードで切り替える。プリセットは「展示室」と「神殿（エーゲ海の青空と自然光）」の2つ。神殿では像の大理石に自然光と影が落ちるよう、ディレクショナルライトの向きと強さも切り替える。

### 2.7 タスク HUD

- 担当プレイヤーには、手元に追従するパネルで「🔔 TASK」、手順、達成したときのチェックを表示する。
- 担当でないプレイヤーには「プレイヤーA が操作中」と表示する。相手の選択範囲、ストローク、掴んでいる部位の動きは空間にそのまま見えるので、2人とも同じ変化を見られる。
- 操作を待つステップでは、一定時間たっても完了しなければヒントを表示する（判定ゾーンの強調、目標位置のガイドなど）。

### 2.8 学者 NPC・ナレーター

- 学者A（考古学）と学者B（構造力学）は **VR 内の NPC** として実装する。台詞は事前に用意した音声（生声または合成音声。台詞ごとに1ファイル）で再生し、頭上に字幕を出す。音源は位置付き（3D）、口パクは Basis 同梱の uLipSync を流用する。
- ナレーターは位置を持たない 2D 音声で、視界の下に字幕を出す。

## 3. ステップ定義

[A] / [B] は担当プレイヤーの操作で進むステップ。それ以外は台詞の再生が終わると自動で進む。

| # | 場面 | 内容 | 操作（部品） | 完了条件 | 到達する版・演出 |
|---|---|---|---|---|---|
| 0 | ロビー | 接続待ち | — | 2人そろう、または運営が開始 | 薄暗い展示室 |
| 1 | Opening | ナレーター導入 | — | 台詞終了 | スポットライトの当たった腕のない像 |
| 2 | Scene 1 | 学者Aが林檎説を語り、学者Bがモデル化を頼む | — | 台詞終了 | |
| 3 | Scene 1 [A] | 「手のひらに林檎がのった水平に伸びる左手を追加」 | Voice | 音声指示が完了 | **Ver 1.0**（左腕を前方に水平に伸ばし、手のひらに林檎） |
| 4 | Scene 1 | 学者Bの懸念（付け根の負担、林檎の持ち方） | — | 台詞終了 | |
| 5 | Scene 2 | 学者Aが学者Bの案を頼む | — | 台詞終了 | |
| 6 | Scene 2 [B] | 林檎を範囲選択し、手の下へ移動 | Selection（林檎）→ Manipulate（平行移動） | 林檎が目標位置でスナップ | 林檎が手の下へ |
| 7 | Scene 2 [B] | 腕を範囲選択し、「上からボールを包み込むように林檎を持ち直す形に修正」 | Selection（左手〜前腕）→ Voice | 音声指示が完了 | **Ver 1.1**（指先で上から林檎をホールド） |
| 8 | Scene 2 | 学者Aが「自然なカーブ」を求める | — | 台詞終了 | |
