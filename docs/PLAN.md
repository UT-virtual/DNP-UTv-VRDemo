## 1. 前提と技術方針

| 項目 | 決定内容 |
|---|---|
| ベース | [BasisVR/basis](https://github.com/BasisVR/basis) の `long-term-support-20260916` ブランチをフォーク（git remote `upstream`） |
| Unity | **6000.5.10f1**（Basis LTS の指定バージョン）／URP／OpenXR |
| ターゲット | Meta Quest（2 / 3 / 3S / Pro）向け APK（Android, IL2CPP, ARM64, Vulkan） |
| マルチプレイ | LAN・最大2人。**プレイヤーA の Quest が Basis のホストモード（サーバーをプロセス内で起動）**、プレイヤーB がその IP に接続。ポート 4296 |
| 会場ネットワーク | Quest 2台が端末同士で通信できるルーターを用意する（AP アイソレーションは無効にする） |
| 体験形態 | 基本は立ったまま体験する。必要になったら Basis 標準の左スティック移動を有効にする |
| ワールド | `Assets/DNPDemo/Scenes/DNPDemo_Main.unity` をビルドの先頭シーンにして直接起動する。シーンは機能ごとのプレハブ（DemoSystems、Lighting、環境、像、比較台、学者）を並べた構成にし、普段の作業はプレハブを編集する。シーンとプレハブは Unity 上で直接編集し、それを正とする（[CONTRIBUTING.md](../CONTRIBUTING.md)） |
| プレイヤー間の会話 | 2人は同じ会場で声が届く距離にいるので、ボイスチャットは使わない（マイクはミュートのまま） |
| 生成AI | 生成・修正の結果は事前に用意した版（モデルとポーズ）で表現する。決まった操作を判定したら、遷移演出とともに次の版へ切り替える |
| 音声指示 | 疑似認識。音声入力モードのペンでトリガーを押している間だけマイクを取り込み、音量で発話を確認する。離したら台本の文を認識結果として表示する（§2.4）。音声は相手に送らない |
| 独自コード | `Assets/DNPDemo/` 以下に置く（asmdef：`DNPDemo.Runtime` / `DNPDemo.Editor`） |
| ワールド UI | ワールド空間の uGUI には `BasisGraphicUIRayCaster` を付け、配下のオブジェクトをすべて `UI` レイヤーに置く。Basis は、レーザーが当たったコライダーが `UI` / `OverlayUI` レイヤーにあるときだけ、レーザーとカーソルを描画してボタン操作を通す |
| Basis 本体の改造 | 必要最小限にとどめ、変更箇所はすべて [BASIS_PATCHES.md](BASIS_PATCHES.md) に記録する（upstream をマージするときの衝突対策） |

### 1.1 リモート接続（インターネット越し）に対応する場合のコスト

Basis の通信層（LiteNetLib / UDP）は、もともとインターネット上のサーバーに接続する前提で作られている。そのため、**通信の仕組み自体を新しく作る必要はない**。コストが変わるのは「どこでサーバーを動かすか」と「ホスト＝プレイヤーA という前提をどう扱うか」の2点。

| 方式 | 内容 | クライアントの改修 | 運用・インフラ | 目安 |
|---|---|---|---|---|
| **A. 専用サーバー（推奨）** | クラウドの VPS などで `Basis Server` を動かす（Docker Compose 同梱）。2台ともそのサーバーに接続する | ・接続先アドレスを選ぶ UI<br>・**ロール決定とシナリオの進行管理を「ホスト＝プレイヤーA」から切り離す**（ロビーで役を選ぶ方式、進行管理は Basis の所有権（ownership）で決める） | VPS の構築、UDP 4296 の開放、パスワード設定。少額の月額費用がかかる | 3〜5人日 |
| B. ホストモードのまま | プレイヤーA 側のルーターで UDP 4296 をポート開放し、プレイヤーB がグローバル IP に接続する | 接続先の入力 UI のみ | ホスト側のネットワークにポート開放と固定 IP（または DDNS）が必要。会場の回線やモバイル回線（CGNAT）では使えないことが多い | 0.5人日。ただし接続できる環境が限られる |
| C. NAT 越え／リレー | ポート開放なしで端末同士を直接つなぐ | Basis にはこの仕組みがないので、マッチングとリレーを自作する | リレーサーバーの運用 | 2週間以上 |

- 方式 A のコストの大半は「ホスト＝プレイヤーA」をやめる改修にある。後から対応しやすいように、**ロールの決定とシナリオ進行の権限を判定する処理を1か所（`DemoRoleService`）にまとめ**、ほかのコードは `IsHostMode` を直接参照しないようにする（§2.1）。こうしておけば、リモート対応時に差し替えるのはこのサービスとロビー UI だけで済む。
- 2人で進めるシナリオなので、インターネット越しの遅延（数十〜100ms 程度）による体験への影響は小さい。離れた場所の2人が会話するには、Basis 標準の Opus 通話でボイスチャットを有効にすればよい。その場合、音声指示の取り込み中は相手に送らないよう、音声指示とボイスチャットを切り分ける。

## 2. アーキテクチャ

### 2.1 起動〜接続

1. APK を起動すると `DNPDemo_Main` がワールドとして読み込まれる（Basis の起動処理はシーンに依存しない）。
2. **ロビーパネル**（ワールド空間の uGUI。`BasisGraphicUIRayCaster` で Basis のレーザーから操作する）に「プレイヤーA（ホスト）」「プレイヤーB（参加）」の2つのボタンを出す。
   - A を選ぶと、`DemoSessionService` が人数上限2・デモ用パスワードで `BasisConnectionService.ConnectAsync(entry, name, isHostMode: true)` を呼ぶ。接続できたら UDP ビーコン（`LanHostBeacon`）を1秒ごとにブロードキャストし、パネルに自分の LAN の IP を表示する。
   - B を選ぶと、`LanHostScanner` がビーコンを待ち受ける。ホストが1台だけ見つかれば自動で接続し、複数なら一覧から選ばせる。受信している間は Android の `MulticastLock` を取得する。
   - 予備として、テンキーによる IP の手入力（最後に使った IP を初期値にする）と、Basis 標準の deep link `basisdemo://IP:4296` を使える。
   - 接続の状態は `BasisNetworkConnectionWatchdog.Health` から読み取る。B の再接続は Basis の watchdog に任せる。
3. ロールの決め方：ホスト = プレイヤーA、クライアント = プレイヤーB。決まったロールに応じて `Spawn_PlayerA/B` の位置へ移動する。
   - ロールの判定とシナリオ進行の権限判定は `DemoRoleService` に集約する（`GetLocalRole()` / `GetRole(playerId)` / `HasScenarioAuthority`）。現在の実装では、ホストならプレイヤーA かつ進行の権限あり、と判定する。
   - 各端末は自分のロールを相手に通知し、「プレイヤー ID → ロール」の対応表を持つ。知らない相手から通知を受けたら自分のロールを返信するので、参加の順番によらず両者がそろう。
   - `IsHostMode` を参照するのは `DemoSessionService` と `DemoRoleService` だけにする。
4. 起動時のダイアログ：新規インストールした Quest 3S で確かめたところ、起動からロビーまでに出るのは、マイク（`RECORD_AUDIO`）の権限ダイアログだけだった。Basis の初期化でマイクを使い始めたときに、ロビーの上に出る。マイクは音声指示に使うので、権限はインストールのときに `adb shell pm grant` で許可しておく（手順は [README.md](../README.md) の「Quest へのインストール」）。
   - 起動時のダイアログ、フォーカスの出入り、権限の状態は、Development Build で動く `DialogProbe`（`Scripts/Runtime/Diagnostics/`）がログに出す。Basis を更新したときは、新規インストールでこのログを取り直して確かめる（手順は [CONTRIBUTING.md](../CONTRIBUTING.md)）。

### 2.2 シナリオ進行（中核）

コードは `Scripts/Runtime/Scenario/`、データは `Data/ScenarioData.asset`。

```
ScenarioData (ScriptableObject)   … ステップ定義の配列。シナリオの改訂はこのデータの編集で対応する
   └ ScenarioStep: Id / 運営表示名 / 担当ロール / 完了条件 / タスク文 / 操作定義（InteractionPart の列）/ キュー列
ScenarioProgress（純 C#）        … 正となる状態 {seq, ステップ番号}。遷移のたびに seq が変わる（同じステップへの移動は、そのステップの再生し直し）
ScenarioDirector (BasisNetworkBehaviour)
   ├ 進行権限を持つ端末（DemoRoleService.HasScenarioAuthority）が状態を持ち、変わるたびに ReliableOrdered で配信する
   ├ 参加・再接続した端末は OnNetworkReady で状態を要求し、権限側が返信する
   ├ ほかの端末は「操作完了」と運営操作を権限側へ送るだけ。どちらも seq 付きで、古いステップ宛ては捨てる
   ├ どちらかのプレイヤーがいない間は、台詞が終わっても次へ進まない。戻ってきたら、現在のステップを2人とも頭から再生し直す
   └ 権限側はステップが変わるたびにステップの Id を保存する（ScenarioCheckpoint、PlayerPrefs）。ホストを始めたとき、
     保存されたステップがロビーと結びの間なら、前回は中断したとみなして、そのステップを再開候補（ResumeStepIndex）として
     状態と一緒に配る。再開候補があるロビーは、2人がそろっても自動では進まず、運営が再開か最初からかを選ぶ。
     再開候補があるロビーでは保存を上書きしないので、選ぶ前にもう一度再起動しても再開候補は残る
StepCompletion（完了条件）
   ├ CuesFinished … 権限側でキューの再生が終わり、2人がそろっていれば進む
   ├ PlayersReady … ロビー。2人目が参加した時点で進む（リセット後に2人ともいる場合と、再開候補がある場合は運営が開始する）
   ├ Interaction  … 担当ロールの端末で操作定義の部品がすべて完了すると、InteractionRunner が ScenarioDirector.ReportInteractionComplete() を呼んで進む
   └ Manual       … 運営の操作でのみ進む（結び）
   運営スキップはどの条件でも常に使える
ScenarioCue（キュー）… LineCue（話者＋字幕＋音声）/ WaitCue / SoundCue / SetObjectActiveCue / BannerCue / StatueVersionCue / MatchPoseCue / PlaceAtSketchCue / GuideSnapCue（§2.5）/ EnvironmentCue（§2.6）
   └ 見た目を後に残すキュー（永続キュー）は ApplyInstant を実装する
ScenarioPlayer … ステップに入るたびに、舞台を初期状態に戻し、それまでのステップの永続キューを即時に適用してから、
                 現在のステップのキューを頭から再生する
ScenarioStage  … シーン側の窓口（効果音、バナー）。SO はシーンを参照できないため、話者（音声と字幕）とキー付きオブジェクトは、
                 対象のプレハブに付けた ScenarioSpeakerBinding / ScenarioObjectBinding を、シーンの読み込みが終わってから（Start 時点で）集めて引く。
                 キー付きオブジェクトの表示状態とローカルの位置・回転を集めた時点で記録し、舞台を初期状態に戻すときに復元する。
                 それ以外の状態（像の版など）は、キー付きオブジェクトのコンポーネントが IStageResettable を実装して自分で戻す
```

- 見た目の状態はすべてステップ番号から決まる。途中参加・運営のジャンプ・通常の進行のどれでも同じ見た目になり、同期は {seq, ステップ番号} だけで済む。途中参加した端末は、現在のステップの台詞を頭から再生する。
- 操作中の途中経過（選択範囲、ストローク、掴んでいる部位の位置）だけは、相手にも見えるよう別途送る（§2.4 の「同期」列）。ステップが進んだ時点で途中経過は破棄し、ステップ番号から決まる状態に戻す。ペンで動かした部位も、`ScenarioStage` が初期状態に戻したうえで、それまでのステップの永続キューが結果を表示する。
- 音声クリップが未設定の台詞は、文字数から求めた時間（`LineTiming`）だけ字幕を出す。学者の字幕は頭上（`SubtitleAnchor`）、ナレーターの字幕は視界の下に追従して出す。
- **運営用デバッグ操作**：左右のスティックを同時に2秒押し込むと、運営パネルが目の前に開く。次へ、戻る、任意のステップへの移動（◀ ▶ で選んで「移動」）、ロビーへ戻す（次の体験者へ）、中断したステップからの再開（再開候補があるときだけ表示）ができる。どちらの端末からでも操作でき、権限のない端末の操作は権限側へ送られる。エディタとデスクトップでは F9 でパネルの開閉、F10 で戻る、F11 で次へ。パネルには音声指示のしきい値の調整（§2.4）もある。運営の手順は [README.md](../README.md) の「運営の操作」にまとめている。
- **次の体験者への交代**：結びは運営の操作で待機する。運営が「ロビーへ戻す」を押すとステップ0 に戻り、舞台はステップ番号から初期状態になる。ステップ番号で決まらないものは、`VisitorReset`（`Scripts/Runtime/Players/`、DemoSystems の `Scenario`）が、ロビーのステップに入るたびに各端末で戻す。自分のプレイヤーをロールの開始位置へ移動し（`DemoSpawnService.ReturnToRoleSpawn`）、自分のロールのペンを手から離して開始位置へ戻し、モードと半径を初期値にする（`SpatialPenController.ResetForNextVisitor`）。ペンは戻す端末が姿勢の同期の所有権を取るので、相手の端末でも元の位置に戻る。
- シナリオ一式は DemoSystems プレハブの `Scenario` に置く。メニュー「DNP Demo/Setup/Install Scenario Into DemoSystems Prefab」で組み込む（データと UI プレハブがなければ先に生成する）。インストーラーは足りない部分（ツール、効果音の `SePlayer`、`VisitorReset`、運営パネルの欄）だけを追加するので、組み込む部品が増えたら再実行する。それ以外はプレハブ・データを直接編集する。
- キューが使う話者とキーがシーンにそろっていることは、Editor テスト（`ScenarioSceneBindingTests`）で確かめる。

### 2.3 空間ペン

プレイヤーA・B が1本ずつペンを使う。ペンは空間に置かれていて、掴んでいる間だけ手に付いてくる。ペンのモードは体験者がメニューで選び、各ツールはペンのモードが現在の部品のモード（`InteractionPart.Mode`）と一致しているときだけ入力を受け付ける。どのモードを使うかは HUD の手順文で案内する。

コードは `Scripts/Runtime/Pen/`。ペンは `Prefabs/Pen/SpatialPen.prefab`（ペンのモデルのバリアント。ピックアップ、同期、掴むためのコライダーを持つ）で、`DemoSystems/Pen` にプレイヤーA・B 用の2本（`Pen_PlayerA` / `Pen_PlayerB`）を置いている。ペンの開始位置は、DemoSystems 内の `Pen_PlayerA` / `Pen_PlayerB` の位置で決まる。

ペン単体の動作確認には `Art/Pen/PenTestScene.unity` を使う。ネットワークへの接続もロールも不要で、再生すると `PenTestHarness`（`Scripts/Runtime/Pen/Testing/`）がシーン内のペンを `SpatialPenController` に渡す。掴む・離す、ホバー時のハイライト、トリガー、半径とペンの長さ、モードの切り替え（メニューとボタン）を確認できる。範囲選択も試せる：`SelectionTestHarness`（`Scripts/Runtime/Interaction/Selection/Testing/`）が、範囲選択モードでトリガーを押すたびに選択範囲を記録して表示し、離すと `SelectionTarget`（白い球と同じ大きさの球ゾーン）に対して判定して、結果をコンソールに出す。線画も試せる：`StrokeTestHarness`（`Scripts/Runtime/Interaction/Stroke/Testing/`）が、線画モードで描いた線を表示し、ペン尻の消しゴムで消せるようにする。離すたびに、ガイドなら `StrokeStart` から `StrokeEnd` まで届いたか、線画なら外接サイズを判定して、結果をコンソールと `StrokeTestPanel` に出す。ガイドと線画は、このパネルのボタン（VR ではレーザー、デスクトップではマウスで押す）で再生中に切り替えられる。切り替えると線はすべて消え、始点・終点の球はガイドのときだけ表示する。部位の操作も試せる：`ManipulateTestHarness`（`Scripts/Runtime/Interaction/Manipulate/Testing/`）が、物体移動モードのペンで右の箱（平行移動）と左の棒（支点まわりの回転）を掴めるようにし、目標の姿勢をゴーストで示す。離すたびに判定して結果をコンソールに出し、成功したら目標へスナップして、1.5 秒後に元の位置へ戻す。音声指示も試せる：`VoiceTestHarness`（`Scripts/Runtime/Interaction/Voice/Testing/`）が、音声入力モードでトリガーを押している間マイクを取り込み、左手前のテキスト（`VoiceTestStatus`）に音量としきい値を出す。有音が必要な長さに達した時点で認識結果を出し、離すと結果をコンソールに出す。端末間の同期とロールごとの表示は対象外で、`DNPDemo_Main` を2台で接続して確認する。

| 要素 | 仕様 |
|---|---|
| 保持 | Basis のピックアップ（`BasisPickupInteractable`）で掴む。左右どちらの手でも、ペン本体（ペン尻から 30cm、カプセルコライダー）から 15cm 以内でグリップを押している間だけ保持し、掴んだ瞬間の手（IK 後の手）との位置関係を保つ。離すとその場で空中に固定される（Rigidbody なし）。掴めるのはそのペンのロールの端末だけ（`SpatialPenView` が `CanHoverInjected` / `CanInteractInjected` で絞る）。ホバー中はペン本体をハイライトする |
| モード選択 | メインメニュー（Y）の「空間ペン」を押すと、ホットバーの真上に横長のサブメニューが開き、範囲選択／物体移動／音声入力／線画から選ぶ（`PenModeSelection`）。初期値は範囲選択。ペンを持っている間は、持っている手の下のボタン（右手なら A、左手なら X）を押すたびに、メニューの並び順で次のモードへ切り替わる（線画の次は範囲選択）。掴んだときにすでに押していたボタンは、一度離すまで数えない |
| 伸縮 | 保持中に右スティックの上下でペンを伸び縮みさせる（左手で持っているときも右スティック。左スティックは歩行、右スティックの左右は旋回）。`PenBody` のブレンドシェイプ `Extend` を 0〜1 で動かし、全長は 30〜130cm。範囲選択モードではスティックが半径を変え、長さは半径から決まる（次の行）。それ以外のモードではスティックが長さを直接変え（全域を 1.5 秒）、その長さは範囲選択以外のモードで共有して、モードを切り替えても保つ。ペン先の位置（線画の線、物体移動の掴む位置）と、ペン先の部品（`PenSelectArea`、`PenManipulator`）は伸びに合わせて動く。ペン尻の部品（`PenMicrophone`、`PenEraser`）は動かない |
| 範囲選択 | ペン先に半透明の赤いスフィア（`PenSelectArea`）を出す。保持中に右スティックの上下で半径を 0.025〜0.5m の範囲で変える。スフィアが持ち手にかからないよう、半径 0.05m から 0.5m にかけて `Extend` を 0 から 1 へ伸ばす |
| 音声入力 | ペン尻にマイクヘッド（`PenMicrophone`）を出す。保持中に、持っている手のトリガーを押している間、インジケーター（マテリアル `PenMicIndicator`）を赤から緑にする |
| 線画 | ペン尻に消しゴムの球（`PenEraser`、半径 0.025m）を出す。線の色は白 |
| 物体移動 | ペン先に、上下左右へ伸びる矢印のギズモ（`PenManipulator`、全体で 0.2m）を出す。掴む判定はギズモの大きさとは別で、ペン先を中心とした半径 0.05m の球（`PenGeometry.GrabRadius`、表示しない）が部位の掴む範囲に触れている状態でトリガーを押すと掴む |
| 入力の窓口 | `SpatialPenController` が、保持中のトリガー（`IsTriggerHeld`、`TriggerPressed` / `TriggerReleased`）、ペン先の位置、半径、モードを各ツールに渡す。トリガーは持っている手のものを読む。レーザーがメニューやパネルに当たっている状態で押し始めたときは無視し、押している途中でレーザーが UI に当たっても押したままとして扱う（線が途切れない）。Basis からの入力の読み取りは `PenInputReader` に集約する。デスクトップでは Basis のピックアップの操作（クリックで掴み、右クリックで離す）で持ち、T（トリガー）、N/M（右スティックの上下）、G（モード切り替えのボタン）で代用する |
| 同期 | ペンの姿勢は Basis の `BasisPickupSyncNetworking` が同期する（保持中は相手側でもプレイヤーの手に付く。掴んだ端末が所有権を取る）。それ以外は `SpatialPenSync` が、自分のペンのモード、半径、長さ、保持とトリガーの状態を、半径か長さが変化している間は最大 20Hz（Unreliable）で送る。モード・保持・トリガーの変化はすぐに送る。止まって 0.3 秒たったら最終状態を Reliable で送る。途中参加した端末には現在の状態を直接送る |
| 既存機能との競合 | Basis の機能のうちデモで使わないものは、起動時に `Scripts/Runtime/BasisPolicy/` で無効化する。X（ミュート切り替え）、A（ジャンプ）、グリップ（飛行中の下降）の割り当てを外し（A と X はペンのモード切り替えに使う）、マイクは常にミュートに固定し（音声指示の取り込みは使える）、マイクアイコンは表示しない。アバターを掴む機能と、空間を掴んで移動する機能は設定でオフにする。配置物を掴む機能（`DisablePropPickup`）はペンに使うのでオンに固定する。ワールドに置くピックアップはデモのものだけで（配置物を出すライブラリとカメラはメニューから外している）、掴める端末はピックアップごとに絞る |
| メニュー | Y で開く Basis のメインメニューは、Basis 標準の項目をすべて外し、デモの項目（`Scripts/Runtime/Menu/` の `DemoMenuProvider` 派生）だけを置く。ペンのモードの選択と、背景パネル・履歴パネルを開くのに使う。項目は、ホットバーの上に選択肢を並べる `DemoBarMenuProvider`、横に縦長のページを開く `DemoPageMenuProvider`、メニューを閉じて処理を実行する `DemoMenuProvider` の直接の派生（「背景」「モデルの履歴」）の3種類 |

### 2.4 ペン操作の共通部品

各ステップを個別に実装せず、次の部品の組み合わせで操作を定義する。ステップの操作定義は「部品の種類＋パラメータ（判定ゾーン、目標、制約、台本の文）」として ScenarioData に持たせる。

| 部品 | 操作 | 完了判定 | 同期 |
|---|---|---|---|
| `SelectionTool` | トリガーを押している間、スフィアが通った軌跡を半透明の選択範囲としてマークする。離すと1回分の選択が確定する | 指定した部位ゾーン（林檎、左肩〜肘、右手首など）のそれぞれについて、体積の一定割合（初期値 50%）以上を選択範囲が覆い、かつ選択範囲のサンプルのうち一定割合（初期値 90%）以上がいずれかの指定ゾーンに重なっていれば成功。満たさなければ選択範囲をフェードアウトで消して、もう一度やってもらう | 成功して確定した選択範囲のサンプル列（Reliable で1回）。描いている間、相手にはペンの動きだけが見える |
| `StrokeTool` | トリガーを押している間、空中に線を描く。トリガーを離している間は、ペン尻の消しゴムに触れた線が1本まるごと消える | 線を離すたびに判定する。ガイドモード：その線が始点ゾーンと終点ゾーンの両方に届いていること（向きは問わない）。届かなければ線をフェードアウトで消す。線画：残っている線全体の外接サイズが一定以上であること。足りなければ線を残し、描き足してもらう | 描画中の点（最大 10Hz でまとめて送る）、線の確定、消去。途中参加した端末には、その時点の線をまとめて送る |
| `ManipulateTool` | 物体移動モードのペン先を部位に当て、トリガーを押している間だけ掴んで、ステップごとの制約の範囲で動かす。制約は「平行移動（範囲つき）」または「支点まわりの回転（軸と角度範囲つき）」。目標の姿勢を半透明のゴーストで示す | 離すたびに判定する。目標の姿勢から許容範囲内なら、目標へスナップして完了。回転では、しきい値を超えた角度で離したら完了とする指定もできる（ステップ9）。満たさなければ離した位置に残り、もう一度掴める | 操作中は制約パラメータを最大 20Hz（Unreliable）で送り、離したときとスナップを Reliable で送る。途中参加した端末には現在の値を送る |
| `VoiceCommandTool` | 音声入力モードのペンでトリガーを押している間、タスク HUD に「音声入力中…」と表示する。その間だけ `BasisLocalMicrophoneDriver.AddCaptureHold()` でマイクを取り込み（ミュートのままなので送信はされない）、`averageRms` がしきい値を超えた時間で発話を検知する。離したら `ReleaseCaptureHold()` | 押している間の有音が一定時間に達した時点で、台本の文を認識結果としてタスク HUD に表示する（「トリガーを離すと決定します」）。その状態でトリガーを離すと完了する。達する前に離したら、やり直すよう表示する | 完了イベントのみ（表示は担当の端末だけ） |
| `HistoryTool` | メインメニューの「モデルの履歴」で開く履歴パネル（`HistoryPanel`）で版を選び、「モデルを復元」を押すと、その版を比較台に表示する | ステップで指定した版を復元した | 復元した版の ID |
| `BackgroundTool` | 音声指示で生成した背景が、背景パネル（`BackgroundPanel`）に加わる。その背景を選んで「背景を適用」を押す | ステップで指定した背景を適用した | 完了イベントのみ |

- 各部品は、トリガーなどの入力を `SpatialPenController` から受け取る（§2.3）。グリップはペンの保持に使うので、`ManipulateTool` で部位を掴むのもペンのトリガーで行う。
- 部品の内部表現：選択範囲はスフィアのサンプル列（位置＋半径）で記録し、サンプル間隔は半径に比例させる。ストロークは点列で記録し、LineRenderer で描く。
- 範囲選択の実装（`Scripts/Runtime/Interaction/Selection/`）
  - `SelectionPart` は対象ゾーンをキーの列（`TargetZoneKeys`）、はみ出しの許容率（`RequiredInsideRatio`）、被覆率（`RequiredCoverage`）で持つ。被覆率は `SelectionCoverage` が、ゾーンの外接ボックスに約 1000 点の格子を張り、ゾーン内の点のうち選択球に入る割合として求める。`DetectionZoneGroup` は1つのゾーンとして扱い、含まれるゾーン全体に対する被覆率を見る。キーで指すオブジェクトには `DetectionZoneGroup` か `DetectionZone` を付け、`ScenarioObjectBinding` でキーを登録する。キーの割り当て漏れは `ScenarioSceneBindingTests` が、キーの空や重複は `ScenarioData.Validate` が検出する。キーが1つでも解決できない部品は、判定が常に失敗する（運営スキップで進める）。
  - `SelectionSampler` は、前のサンプルから「半径 × 0.5」以上動いたら（半径の変化も移動に数える）サンプルを足し、1フレームで大きく動いたときは間を補間する。1回の選択は最大 512 サンプル。判定は `SelectionJudge`、送信形式は `SelectionMessage`（1サンプル 8 バイト、最大約 4KB）。
  - 表示は `SelectionVolumeView` が、低ポリの球（320 ポリゴン）を `Graphics.RenderMeshInstanced` で1回の描画呼び出しにまとめて描く。シェーダー `DNPDemo/SelectionVolume`（`Art/Interaction/Selection/`）はステンシルの最上位ビットで各ピクセルを1回だけ塗るので、球の重なりが濃くならない。色は半透明で、全体がゆっくり明滅し、各球の縁を視線の向きに応じて明るく光らせる（フレネル）。
  - 押している途中でメニューからモードを変えると、その選択は判定せずに破棄する。
  - 確定した選択範囲は、次の部品（音声指示など）の間も表示し、ステップが進むと消す。次の部品の途中で再接続した端末には、確定済みの選択範囲は表示されない（`InteractionRunner` が現在の部品宛ての途中経過だけを配るため）。
- 線画の実装（`Scripts/Runtime/Interaction/Stroke/`）
  - `StrokePart` は `Goal`（`Guide` / `Sketch`）を持つ。ガイドは始点・終点ゾーンのキー（`StartZoneKey` / `EndZoneKey`）、線画は外接ボックスの最長辺の下限（`MinExtent`、初期値 0.15m）を持つ。ゾーンのキーは範囲選択と同じく `ScenarioObjectBinding` で解決し、解決できないキーがあるとガイドの判定は常に失敗する。
  - `StrokeRecorder` がペンの入力から線を作り、消しゴムを動かす。点は前の点から 5mm 以上動いたら足す。1本は最大 1024 点、1つの部品の線は合計 4096 点・255 本まで（`StrokeSet`）。押している途中でメニューからモードを変えると、その線は破棄する。消しゴムは線画モードのペンを持ち、トリガーを離している間だけ働く。
  - 判定は `StrokeJudge`。ガイドは、線の各点を線の太さの球としてゾーンに重なるかを見る。
  - 送信形式は `StrokeMessage`（1点 6 バイト）。描画中の点の追加、線の確定、消去、全体（途中参加用）の4種類を、すべて ReliableOrdered で送る。
  - 表示は `StrokeView` が、線ごとにプールした LineRenderer（幅 6mm、`Art/Interaction/Stroke/StrokeLine.mat`）で描く。フェードアウトは線を細くして表現する。
  - 線は次の部品（音声指示など）の間も表示し、ステップが進むと消す。
  - 部品が終わったときに残っている確定済みの線は、`StrokeTool.LastResult`（`StrokeResult`。部品のステップと線ごとの点列）にコピーして保持する。部品が終わるのは、同じステップの次の部品に移ったときか、ステップが進んだとき。ガイドで外れた線はその時点で消えているので含まれない。担当の端末でも相手の端末でも同じ手順で保持するので、通信は増えない。ステップが進んでも消さず、次の線画の部品が始まると置き換える。部品が終わった後に途中参加した端末では空のままになる。キューは StrokeTool に付けたキー `Strokes`（`StrokeTool.BindingKey`）から読む。ステップ14 の手鏡の位置（§2.5 の `PlaceAtSketchCue`）に使う。ステップ12 の腕のスナップは既定の形（§2.5 の `GuideCurve`）を使い、描いた線は使わない。
- 部位の操作の実装（`Scripts/Runtime/Interaction/Manipulate/`）
  - `ManipulatePart` は、動かす対象のキー（`TargetKey`）、掴む範囲のゾーンのキー（`GrabZoneKey`。空なら対象自身のゾーン）、制約（`Constraint`）を持つ。平行移動は目標マーカーのキー（`GoalKey`）、開始位置からの最大距離（`MaxDistance`）、スナップ距離（`SnapDistance`）を持ち、スナップすると目標マーカーの位置と向きに合わせる。回転は支点のキー（`PivotKey`）、支点のローカル空間の軸（`Axis`）、角度の範囲（`MinAngle` / `MaxAngle`。部品の開始時の姿勢を 0° とする）、完了条件（`Completion`：目標角度 `TargetAngle` ± `SnapAngle` でスナップ、または `ThresholdAngle` を超えて離す）を持つ。キーは範囲選択と同じく `ScenarioObjectBinding` で解決し、解決できないキーがあると操作できない（運営スキップで進める）。
  - 制約の計算は `ManipulateConstraint`。部品が始まった時点の対象のワールドの姿勢を起点にし、動かした量を `ManipulateValue`（平行移動は変位、回転は角度）で表す。平行移動は、掴んでからのペン先の変位を最大距離の球に収める。回転は、ペン先を軸に垂直な平面へ投影し、フレームごとの角度の差を積み上げる（±180° をまたいでも途切れない）。ペン先が軸から 2cm 以内のときは角度を更新しない。
  - 入力は `ManipulateGrabber`。押している途中でメニューからモードを変えると、その位置で離したものとして扱い、判定はしない。
  - 送信形式は `ManipulateMessage`（20 バイト）。Unreliable と Reliable は到着順が保証されないので、送信カウンタを付け、受信側は古いものを捨てる。受信側はドラッグの値へ補間しながら動かし、スナップは同じ時間（0.25 秒）で吸着させる。
  - ゴーストは `ManipulateGhostView` が、対象の MeshRenderer のメッシュを目標の姿勢に `Graphics.RenderMesh` で描く（`Art/Interaction/Manipulate/ManipulateGhost.mat`、水色の半透明）。各メッシュは毎フレーム、その時点で対象に付いている姿勢と大きさで描くので、部品の開始時に出現の演出で拡大中の対象（ステップ14 の手鏡）にも追従する。両方の端末に出し、部品が終わったら消す。掴める間と掴んでいる間は、対象を Basis のハイライトで強調する（相手の端末では掴んでいる間）。
  - ツールは対象を元の位置へ戻さない。ステップが変わると `ScenarioStage` が初期状態へ戻す。`ScenarioPlayer` は OnEnable、`InteractionRunner` は Start でステップの変化を購読するので、部品の開始時には舞台がそのステップの状態になっている。
- 音声指示の実装（`Scripts/Runtime/Interaction/Voice/`）
  - `VoicePart` は、認識結果として表示する台本の文（`Transcript`）と、必要な有音時間（`RequiredSpeechSeconds`、初期値 1 秒）を持つ。有音時間は押している間の合計で、途切れてもよい（`VoiceActivityMeter`）。
  - トリガーの押下とマイクの取り込みは `VoiceCommandListener` がまとめる。有音時間が必要な長さに達すると、押している途中でも認識済みとしてマイクを解放し、離した時点の結果に認識済みかどうかを載せる。マイクの取り込みは `MicrophoneCapture` が持ち主ごとに1つだけ保持し、解放の漏れを防ぐ。押している途中でメニューからモードを変えると、取り込みをやめて判定しない。
  - しきい値は `VoiceCommandSettings` が dBFS で持ち（初期値 -40 dB、-70〜-10 dB）、端末ごとに PlayerPrefs に保存する。会場の騒音に合わせて、運営パネルの「音声入力のしきい値」で調整する（`MicrophoneThresholdControl`）。パネルを開いている間はマイクを取り込み（ミュートのまま）、音量メーターにしきい値の位置を重ねて表示する。比べる音量は、Basis がゲイン、ノイズ除去、ノイズゲート、AGC をかけた後の RMS（直近 200ms の平均）。
  - 同じ欄で、Basis が取り込むマイクを確かめて切り替えられる（`MicrophoneSelection`）。Basis はマイクを名前で開き、モード（デスクトップ、VR）ごとに PlayerPrefs に保存する。初回は Unity のデバイス一覧の先頭を選ぶので、PC では Virtual Desktop などの仮想マイク（配信していないときは無音）になることがある。Windows の既定のデバイスを変えても、この選択は変わらない。
  - ミュート中に `AddCaptureHold()` でマイクを起動できるよう、Basis 本体を改造している（[BASIS_PATCHES.md](BASIS_PATCHES.md)）。
  - ツールは状態の文を `InteractionSession.SetStatus()` で渡し、タスク HUD が手順の下に表示する（§2.7）。
- 履歴パネルの実装（`Scripts/Runtime/Interaction/History/`）
  - `HistoryPanel` は、メインメニューの「モデルの履歴」（`HistoryMenuProvider`。ホットバーの右端）を押すと、メニューを閉じて目の前に開き、その位置にとどまる。どちらのプレイヤーもいつでも開ける。右上の × で閉じる。パネルは 960×620mm。
  - パネルには一覧（ブランチ表示）と個別表示の2つの画面がある。開くと一覧を表示し、版のカードを押すとその版の個別表示に切り替わる。個別表示の左上の「一覧へ」で一覧に戻る。
  - 一覧（`HistoryTreeView`）は、到達した版をカード（サムネイルと版名）で並べ、派生元と線でつなぐ。配置は `HistoryTree` が決める。
    - 版は派生元の1列右に置く。派生元の行を続けるが、新しいブランチの版（`VenusVersion.StartsBranch`）と、派生元の行を別の子がすでに続けている版は、それまでのすべての行の下に新しい行を作る。派生元が未設定か未到達の版は、1列目に新しい行を作る。
    - 線は派生元の右端から出し、行が違えば2列の中間で折れて子の左端に入る。
    - 本体の像が今表示している版（最新の版）のカードは青い枠で囲む。
    - 一覧が表示領域に収まらないときは全体を縮小し、中央に置く。カードと線はテンプレートから複製して使い回す。
    - 到達する版が増えるとブランチが伸びる。全版がそろうと6列×3行になる（§2.5）。
  - 個別表示の中央に、選んでいる版を縮小した3Dモデル（`HistoryPreview`）を回転させて表示する。プレビュー用の `VenusStatue` が起動時に全版のモデルを生成しておき、カタログの先頭の版の高さが 0.26m になる縮尺を全版に使う（版を送っても胴体の大きさが変わらない）。プレビューはキャンバスの外に置き、シーンの読み込み時に有効にしておく（モデルの生成を最初に開いたときに回さないため）。
  - 一覧は、現在のステップまでに本体の像に表示された版（`VenusVersionHistory.Collect(ステップ列, ステップ番号 + 1, 像のキー)`）。版のキューはステップの先頭にあるので、現在のステップの版も含める。個別表示では ◀ ▶ で古い版・新しい版へ時系列に送る（`HistoryBrowser`）。開いている間にステップが変わったら一覧を作り直し、選んでいた版が残っていればそのまま表示する。
  - 個別表示の中央下部の「モデルを復元」は、`HistoryPart` の間だけ担当の端末で押せる。それ以外はグレーアウトする。
  - `HistoryPart` は、復元させる版（`TargetVersion`）と、復元した版を表示する像のキー（`ComparisonStatueKey`、初期値は比較台の像）を持つ。`HistoryTool` は、復元された版を比較台に表示し、版の ID を進捗として ReliableOrdered で送る（`HistoryMessage`。長さ1バイト＋UTF-8）。目標の版ならパネルを閉じて完了し、それ以外の版ならパネルに「比較台に Ver 1.2 を表示しました」と出して続ける。相手の端末と途中参加した端末は、受け取った ID の版を比較台に表示する。
  - 比較台の表示はツールが元に戻さない。ステップが変わると `ScenarioStage` が比較台の像を初期状態（空）に戻し、ステップ20の先頭の `StatueVersionCue` が Ver 1.0 を表示する。
  - 見た目は Basis のメニューに合わせる（エディタの `BasisUiStyle`）。背景とボタンは Basis の角丸スプライト（`Circle 512`）、× と ◀ ▶ は Basis のアイコン（`xWhite`、`Foldout Arrow` を回転）、ボタンの色は Basis のボタンと同じ紫グレーと青。
  - プレビューの像はキャンバスの奥（9cm）に置き、パネルの中に像が見える描き方にする。描画順は `HistoryRenderQueues` にまとめている。
    - 背景（`HistoryPanelBackground.mat`、`UI/Default`、キュー 2450）は深度を書かずに描く。
    - 像は、プレビュー用に複製したマテリアル（キュー 2460）で背景の後に描くので、背景色が載らない。
    - パネルと同じ形の板（`Depth`、`DNPDemo/HistoryPanelDepth` シェーダー、キュー 2470）が深度だけを書き、後から描かれるスカイボックスや半透明物がパネルの裏から透けないようにする。
    - ラベルとボタンは通常の UI マテリアルで描くので、像の上に重なり、手やペンには隠れる。
    - Basis のメニューの UI マテリアル（`BasisUI_main`）や背景のシェーダーは常に最前面に描くため使わない。背景は近い暗色で代用している。
    - 既知の問題として、エディタのプレハブ編集画面（Prefab Mode）では、`Depth` の板が有効な間、キャンバス全体が表示されない。ゲーム画面と通常のシーンビューでは正しく表示される。
- メニューから開くパネルの共通部分（目の前に置いてとどめる、× で閉じる、閉じている間はキャンバスごと無効にする、無効のボタンの文字やアイコンを薄くする）は `DemoWorldPanel`（`Scripts/Runtime/Presentation/`）にまとめ、`HistoryPanel` と `BackgroundPanel` が継承する。
- 背景パネルの実装（`Scripts/Runtime/Interaction/Background/`）
  - `BackgroundPanel` は、メインメニューの「背景」（`BackgroundMenuProvider`）を押すと、メニューを閉じて目の前に開く。どちらのプレイヤーもいつでも開ける。大きさと見た目は履歴パネルと同じ（960×620mm）。
  - 左の列に背景をカード（`BackgroundCard`。パノラマを 2:1 で縮小した画像と表示名）で並べる。今の背景のカードは青い枠、選んでいるカードは白い枠で囲む。右側に選んでいる背景のパノラマを大きく出し、その下に表示名（今の背景なら「（表示中）」を添える）、「背景を適用」、状態の文を置く。カードはテンプレートから複製し、縦のレイアウトで並べる。
  - 一覧は、初期の背景（環境コントローラーの `BaselinePreset`）、現在のステップまでの `EnvironmentCue` が適用した背景、実行中の `BackgroundPart` が示す生成結果の順（`BackgroundList.Collect`）。今の背景は、現在のステップまでの最後の `EnvironmentCue` の背景で、なければ初期の背景（`BackgroundList.FindCurrent`）。どちらもステップ番号から決まるので、両方の端末で同じになる。開いている間にステップが変わったら一覧を作り直す。
  - 「背景を適用」は、`BackgroundPart` の間だけ担当の端末で押せる。今の背景を選んでいるときも押せない。
  - `BackgroundPart` は、適用させる背景（`TargetPreset`）と、部品の開始時に担当の端末でパネルを開くかどうか（`OpensPanel`、初期値は開く）を持つ。`BackgroundTool` は、部品の開始時に、両方の端末でパネルの一覧に `TargetPreset` を加える。担当の端末では、`TargetPreset` を選んだ状態でパネルを開く。`TargetPreset` を適用するとパネルを閉じて完了する。それ以外の背景なら「神殿を選んでください」と出す。
  - 背景そのものは、次のステップの先頭の `EnvironmentCue` が切り替える（§2.6）。ツールは環境を変えず、完了のほかは何も送らない。部品の `TargetPreset` と次のステップの `EnvironmentCue` の背景が一致していることは、Editor テスト（`BackgroundTests`）で確かめる。
- 1つのステップで複数の部品を順に使う場合（例：範囲選択 → 音声指示）は、操作定義に部品を順番に並べる。HUD は今どの手順にいるかを示す。

#### 部品の共通インターフェース（`Scripts/Runtime/Interaction/`）

```
InteractionPart（データ）   … 部品の種類ごとのサブクラス。ペンのモード（PenMode）、HUD の手順文、ヒント（InteractionHint、§2.7）を持つ。シーンのオブジェクトはキーで指す
InteractionTool（MonoBehaviour）… 部品を実行するツール。CanRun(part) で担当する部品を判定する
   Begin(session)  … 部品が現在の手順になった。担当の端末では入力を受け付け、それ以外の端末では相手の途中経過を表示する
   End()           … 部品が現在の手順でなくなった。入力を止め、表示は残す（範囲選択を音声指示の間も見せる）
   Discard()       … ステップが進んだ。表示と途中経過をすべて破棄する（結果はステップのキューが表示する）
   OnRemoteProgress … 担当の端末から途中経過を受け取る
   CreateSnapshot()  … 担当の端末で、現在の部品の途中経過全体を返す（途中参加した端末に送る。なければ null）
InteractionSession          … ツールが持つ、1つの部品の窓口。Complete()（完了の通知）と SendProgress()（途中経過の送信）。
                              部品が現在でなくなると無効になり、遅れた呼び出しは無視される
InteractionRunner (BasisNetworkBehaviour、DemoSystems/Scenario/Interaction)
   ├ ステップが変わるたびに部品を順に実行し、担当ロールかどうかと、その部品に必要なペンのモード（RequiredPenMode）を決める
   ├ 担当の端末で部品が完了したら次の部品へ進め、最後の部品で ScenarioDirector.ReportInteractionComplete() を呼ぶ
   └ ツールの通信を1つのネットワーク ID でまとめて運ぶ。メッセージは {seq, ステップ, 部品番号} 付きで、古いものは捨てる。
     部品の切り替わりは担当の端末から送り、ステップに入った端末は担当の端末に現在の部品番号を問い合わせる。
     担当の端末は部品番号と、現在のツールの CreateSnapshot() をその端末にだけ返す
```

- 各ツールは `InteractionPart` のサブクラスと `InteractionTool` のサブクラスを1組で実装し、`InteractionRunner` のツール一覧に登録する。
- 部品は、パラメータの検証（`Validate`）と、シーンに必要なキーの申告（`CollectRequirements`）を実装できる。`ScenarioData` の検証とキーの収集はこれを呼ぶ。
- ツールは `ScenarioInstaller`（メニュー「DNP Demo/Setup/Install Scenario Into DemoSystems Prefab」）で DemoSystems に組み込む。インストーラーは足りないツールだけを追加するので、ツールを増やしたら再実行すればよい。
- 全ステップの操作を本番の部品にしている。音声指示（ステップ3・7・13・15・21）はすべて `VoicePart`、履歴からの呼び出し（ステップ19）は `HistoryPart`、背景の適用（ステップ21）は `BackgroundPart`。シナリオの改訂で、ツールがまだない操作を試すときは、`DummyInteractionPart`（予定の部品のペンモードと手順文を持つ）と `DummyInteractionTool`（担当者が「完了」ボタンを規定回数押すと完了。エディタとデスクトップでは F8）で代用できる。
  - ステップ6：林檎（`Apple`）を範囲選択し、`Goal_AppleUnderHand` へ平行移動する。林檎は Ver 1.0 の左の手のひらにあり、ステップ4 の先頭のキューで表示する。ステップが進むと舞台が林檎を元の位置に戻すので、ステップ7 の先頭の `MatchPoseCue` が手の下に置き直す。
  - ステップ7：左手〜前腕（`Zone_LeftForearm`。Ver 1.0・1.1 の前腕から手を覆うカプセル）を範囲選択し、音声指示する。

### 2.5 像と版の管理

コードは `Scripts/Runtime/Venus/`、データは `Data/Venus/`。

像は正面を -Z に向けて立つ。キーや名前、文書の左右（「左腕」「右手首」など）は、シナリオと同じく像自身の左右を指す。像自身の左肩は +X、右肩は -X にある。腕が胴体の前を横切るポーズでも、部位のキーは操作する腕の左右を指す。
 
| 要素 | 内容 |
|---|---|
| `VenusStatue` | 版を1つずつ表示する像。本体の像（`Statue_Original/StatueAnchor/Venus`、キー `Statue`）と比較台の像（`ComparisonTable/ModelAnchor`、キー `ComparisonStatue`）の2体がある。起動時にカタログの全版のモデルを子として生成して非表示にしておき、版の切り替えでは表示するモデルを切り替えるだけにする（デモ中に生成しない）。初期状態で表示する版（`Baseline`）を持ち、本体は腕なし、比較台は空。舞台を初期状態に戻すと（`IStageResettable`）この版に戻る。切り替えると `VersionChanged` で、前後の版と演出するかどうか（キューの再生なら演出あり、ジャンプや途中参加での即時適用なら演出なし）を通知する。再生していない間は、シーンビューに `EditorPreview` の版をギズモで描くので、ゾーンや目標の配置に使える |
| `VenusVersion`（ScriptableObject） | 版ごとに、Id（`armless`、`v1.0` など。変えない）、表示名（「Ver 1.0」など）、全身モデル（プレハブ）への参照を持つ。胴体の位置・スケール・原点は全版でそろえる。履歴パネルの一覧用に、派生元の版（`Parent`。カタログでこの版より前にあること）、新しいブランチかどうか（`StartsBranch`）、サムネイル（`Thumbnail`）も持つ |
| ブランチ | 腕なし → Ver 1.0、Ver 1.0 から分かれる学者Bの案 Ver 1.1 → Ver 1.2、Ver 1.1 から分かれる Ver 2.0 → Ver 3.0 → Ver 3.1（Ver 1.2 は採用されず、Ver 2.0 は Ver 1.1 から作り直す） |
| サムネイル | メニュー「DNP Demo/Create/Venus Thumbnails」が、全版のモデルを同じ縮尺で、正面から像の左腕の側（+X。正面から見て右）へ 50° 回り込んで少し見下ろす向きに撮り、`Art/Venus/Thumbnails/` に 256px の PNG（背景は透明）で保存して各版に設定する。モデルを差し替えたら再実行する |
| `VenusVersionCatalog`（ScriptableObject） | 版を到達する順に並べた一覧（`Data/Venus/VenusVersions.asset`）。像が起動時に生成する範囲を決める |
| 版の一覧 | 腕なし → Ver 1.0 → Ver 1.1 → Ver 1.2 → Ver 2.0 → Ver 3.0 → Ver 3.1（§3） |
| `StatueVersionCue` | 永続キュー。キーで指した像に版を表示する（空なら何も表示しない）。操作で到達する版は、操作が完了した次のステップの先頭に置く（ステップ0：腕なし、4：Ver 1.0、8：Ver 1.1、10：Ver 1.2、12：Ver 2.0、16：Ver 3.0、18：Ver 3.1。比較台はステップ19の先頭で台を表示し、ステップ20の先頭で Ver 1.0 を表示する）。版はステップ番号から決まるので、同期は不要 |
| 履歴 | `VenusVersionHistory.Collect(ステップ列, ステップ番号, 像のキー)` が、現在より前のステップの `StatueVersionCue` がその像に表示した版を、初めて出た順に1つずつ返す |
| `EnvironmentCue` | 永続キュー。キー `Environment` の `EnvironmentController` に環境プリセットを渡し、クロスフェードで切り替える（ステップ22「結び」の先頭で神殿へ）。後続ステップや途中参加では即時に適用する。詳細は §2.6 |
| 本番モデル | 全版の `VenusVersion.Model` は `Art/Venus/Models/` のプレハブを参照する。各プレハブは足元を原点に置き、高さを 1.91 m にそろえる。右腕を追加する前の版は、Blender の元データと同じく右腕を非表示にする。Ver 3.0 と Ver 3.1 は共通のメッシュ構成を使い、FBX の軸と縮尺をそろえて同じ `Geometry` 変換で配置する。 |
| 操作用モデル | 本体の像は `VenusVersion` に操作用モデルが設定されていればそのモデルを表示する。Ver 1.0 は林檎を分離したモデルを使い、ステップ4〜7では `Targets/Apple` が左手に乗り、操作で動く。履歴と比較台は林檎つきの全身モデルを表示する。 |
| 小物の素材 | Ver 1.0 の操作用 FBX と編集元の `Source~/Venus_Ver1_0_Interaction.blend` は手と林檎のメッシュを持つ。単体の林檎はこの FBX を参照する。ステップ14〜15の単体の手鏡は Ver 3.0 の `Venus_HandMirror` メッシュとマテリアルを使い、手鏡を持つモデルに切り替わる時点で非表示になる。 |
| 仮モデル | メニュー「DNP Demo/Create/Venus Versions」で、仮モデル、`VenusVersion`、カタログのうち足りないものを生成する。仮モデルの定義を更新するときは `VenusAssetBuilder.RebuildPlaceholderModel` で同じパスに再生成する。 |
| 操作対象のオブジェクト | 部位ゾーン、目標マーカー、支点、林檎と手鏡の単体、腕と手のプロキシ、ガイドのカーブは `Statue_Original/StatueAnchor/Targets` に置き、版のモデルとは分ける |
| `MatchPoseCue` | 永続キュー。キーで指したオブジェクトを、別のキーのマーカーの位置と向きに置く。ペンで動かした結果を、次のステップ以降に表示するのに使う（ステップ7 の先頭で林檎を手の下へ、ステップ15 の先頭で手鏡を右手の位置へ） |
| `PlaceAtSketchCue` | 永続キュー。指定したステップ（`SketchStepId`）の線画の外接ボックスの中心に、キーで指したオブジェクトを表示する。向きは置き場所のマーカーに合わせ、位置はマーカーから `MaxOffset` 以内に収める。線画は各端末の `StrokeTool.LastResult` から読む（§2.4）。線画を見ていた端末はどれも同じ線を持つので位置がそろう。線画がない場合（運営のジャンプやスキップ、線画の部品が終わった後の途中参加）はマーカーの位置に出す。再生時は `ScaleInEffect`（子の見た目だけを拡大し、ステップが変わると `IStageResettable` で元の大きさに戻す）で出現させる。ステップ14 の先頭で、手鏡をステップ13 の線画の位置に出すのに使う |
| `GuideCurve` | ステップ11の「ガイドを描く」でプレイヤーが描く「軌跡」の表示用カーブ（3次ベジェ曲線）。判定は始点・終点ゾーンで行い、このカーブは判定に使わない。端点は常にガイドの始点・終点ゾーンの Transform を参照するので、ゾーンの中心と一致する（カーブが保つのは中間の制御点2つだけ）。子オブジェクト `GuideLine`（キー `GuideLine_LeftArm`）が点線として視覚的なガイドを表示し、ステップ11の先頭で表示、ステップ12の先頭で非表示になる |
| `GuideSnapEffect` / `GuideSnapCue` | ステップ12の「ガイドの軌跡に沿って腕がスナップする」演出。ステップ12の先頭の `GuideSnapCue` が、`GuideCurve` に沿って光る線を肩から胸元へ伸ばし（先端に光る球）、届いた時点で次の `StatueVersionCue` が Ver 1.2 → Ver 2.0 を左腕の範囲で切り替える。線はその後細くなって消える。演出は既定のカーブで走らせ、描いた線は使わない（ガイドの判定は両ゾーンに届いたことなので、同じゾーンを結ぶカーブと整合する）。一時的な演出なので、ジャンプや途中参加では表示しない。ステップが変わると `IStageResettable` で止める |
| 操作対象の定義 | 部位ゾーン（林檎、腕、手鏡など）、ギズモの原点（重心）、始点・終点ポーズ、制約（平行移動の範囲、回転の軸と角度範囲）、ゴーストの形状と大きさはステップ定義側に持つ。モデルには ID やピボットを持たせない |
| 部位の確定 | 選択範囲がそのステップの部位ゾーンに一定割合以上重なっていれば、その部位で確定する（ざっくり選択を許容）。外れていれば選択範囲を消してやり直す。確定時、選択範囲を部位の形にスナップして見せる |
| `GestureGizmo` | 操作用の取っ手。ステップに応じて、確定した部位の重心に移動ギズモ（XYZ 矢印）または回転ギズモ（XYZ 3リング）のどちらか一方を出す。中心は重心固定（中心可変は今回のスコープ外）。制約で使わない軸は出さない。部位の形とは無関係 |
| `GhostPart` | 操作対象の目標表示（半透明）。ギズモで動かすのはゴーストだけで、元の像は動かさない。許容範囲内で離すと目標へスナップして完了する。標準の見た目は実物大の簡易プロキシ（林檎ならスフィア、手鏡なら板など）。実物の部位のゴーストは任意（下記） |
| `GuideLine` | 始点から終点へ向かう直線（またはガイド線）を表示し、どこへ動かすかが一目でわかるようにする。移動のステップで使う。回転のステップでは、回転軸と目標角度の目印に置き換える |
| `ModelTransition` | 版の切り替え演出（ディゾルブ、スキャンライン、パーティクル）。どの版の遷移でも同じ仕組みを使い、全身モデルを切り替える。変化した部位の範囲を中心に演出をかける：`StatueVersionCue` の `FocusKey` で指したオブジェクトの範囲（`DetectionZone` ならその形、それ以外は描画の範囲）を、その切り替えにだけ渡す（`ModelTransition.SetBounds`）。空なら像全体。ステップ4・8・10・12 は左腕の範囲（`Focus_LeftArm`）、ステップ16・18 は右腕と手鏡の範囲（`Focus_RightArm`）を使う |
| 比較表示 | 比較台の `VenusStatue` に、指定した版を表示する |
| 履歴の表示 | `HistoryPanel` が、本体の像の履歴をブランチの一覧と、1版ずつの3Dモデルで表示する（§2.4） |
 
**操作の流れ**
 
1. ペンでざっくり範囲選択し、部位ゾーンとの重なりで部位を確定する
2. 重心にギズモが出る（ステップ6・14は移動、ステップ9・17は回転）。あわせて、実物大のゴーストと始点から終点へのガイド線が出る
3. ゴーストを動かして始点・終点を指定する（元の像は動かさない）
（ただし、ステップ9（腕）とステップ17（手首）は、重心まわりの回転だと見た目が不自然になる可能性があるので、ステップ定義の「ギズモ原点」を関節位置に置き換えて対応）
4. 確定したらパーティクル演出で次の版に切り替える
**ゴーストの見た目の方針**
 
- 標準：実物大の簡易プロキシ ＋ 始点から終点へのガイド線。アセット作業は発生しない
- 任意：実物の部位だけを半透明で出す。アセットが間に合った場合のみ M4 で差し替える（FBX 内でサブメッシュ分けが必要）。間に合わなければプロキシのまま出す
**同期**
 
- 操作中のギズモ値は約20Hz（Unreliable）、確定は Reliable で送る
- 相手側にもゴーストの動きと版切り替えが見える


### 2.6 環境の切り替え

`EnvironmentPreset`（ScriptableObject）に、2:1 の Skybox パノラマと露出・回転、展示室の壁の表示、Directional / Spot Light、Ambient、Reflection の設定をまとめて持たせる。`EnvironmentController` は描画中のパノラマをスナップショットしてから次の環境へクロスフェードするため、遷移中の再指定でも画面を飛ばさず目標へ収束する。遷移先のパノラマは最初から自分の露出・回転で描き、混ぜる割合だけを変える。無効のスポットライトは強度 0 として補間するので、点くときは暗い状態から、消えるときは暗くなってから切り替わる。スポットライトの点灯は Keep / On / Off で指定し、Keep は点灯状態を変えない（遷移中に再指定されたときは進行中の遷移先の点灯状態を引き継ぐ）。色・強度・向きなどはどの指定でも適用する。展示室は Keep、神殿は Off。

展示室は、ルートの `EnvironmentFadeGroup` に列挙した Renderer をまとめてフェードする。展示室の FBX はマテリアルごとにメッシュが分かれていて壁だけを選べないため、部屋全体を対象にし、神殿では Env_Temple の大理石の床を見せる。表示中は元の不透明マテリアルと影の設定で描き、フェード中は透明マテリアルに差し替えて影を切り、消えたら Renderer を無効にする。透明マテリアルは自身の面どうしや文字などの透明物と正しく前後判定できないため、フェード中以外では使わない。透明マテリアルは Prefab から参照するアセット（`Art/ExhibitionRoom/Materials/Fade/`）にして、シェーダーバリアントが確実にビルドに入るようにする。URP のエディタ検証は透明な Lit マテリアルの ZWrite を Off に戻すため、`EnvironmentFadeGroup` は初回のフェードでアセットを1つずつ複製し、複製の ZWrite を On にして深度を書く（自身の面どうしが隠し合うように）。アルファは複製の `_BaseColor` に設定する。移動用 Collider はどの状態でも維持する。

反射は、プリセットごとにパノラマから焼いたキューブマップを `RenderSettings.defaultReflectionMode = Custom` で使う。実行時にキューブマップを作り直さないため、Quest でも切り替えの負荷がない。キューブマップは混ぜられないので、キューブマップが変わる遷移では、反射の強度を中間点までに 0 へ下げ、そこで切り替えてから目標の強度へ上げる。

環境光（Ambient）のソースは、展示室が Trilight（グラデーション）、神殿が Skybox。URP はどのソースでも `RenderSettings.ambientProbe`（球面調和関数、SH）で照らす。Skybox は、パノラマから焼いた SH に Intensity を掛けたものを `AmbientMode.Custom` で使う（Unity の Skybox モードは実行時に作り直す必要があるため使わない）。遷移中は画面に出ている SH から目標の SH へ Custom モードで補間するので、グラデーションと空のように異なるソースの間でもなめらかに変わる。Trilight の目標の SH は、色を一瞬適用して Unity の変換結果を読み、遷移の終わりに Trilight モードへ戻しても見た目が変わらないようにする。Intensity は Unity と同じく Skybox にだけ効く。

プリセットは「展示室」と「神殿（エーゲ海の青空と自然光）」の2つ。プリセットは表示名（`DisplayName`）を持ち、背景パネル（§2.4）のカードに使う。神殿のパノラマは JPEG（LDR）で、太陽の明るさを持たないため、背景と反射にだけ使う。像の陰影はディレクショナルライトと Ambient で作る。ディレクショナルライトは、パノラマ上の太陽の位置（u, v）から向きを決める。Skybox は u を方位 `360·(u−0.5) − 回転` 度（+Z から +X 方向）に、v を高度 `180·(v−0.5)` 度に置くので、ライトの Euler は（高度, 方位 − 180, 0）になる。Android の URP アセットはソフトシャドウに対応しないため、神殿の影は Hard にする。Unity は Skybox マテリアルのすべてのパスを描くので、空のシェーダー（`EnvironmentCrossfadePanorama.shader`）は1パスだけにし、遷移のスナップショットは別のシェーダー（`Hidden/DNPDemo/Environment Panorama Snapshot`）で撮る。パノラマの読み取りは両者で `EnvironmentPanorama.cginc` を共有する。DNPDemo_Main の SceneCamera は背景（Clear Flags）を Skybox にし、`EnvironmentController` が差し替える空がそのまま映るようにする。スナップショット用のシェーダーは名前で探さず、Lighting Prefab の `EnvironmentController` に参照を持たせる。

`DNP Demo/Setup/Build Environment Presets` は、展示室の仮パノラマとプリセットを生成し、神殿パノラマのインポート設定（2D、sRGB、Mipmap、Wrap U=Repeat / V=Clamp、2の累乗に縮めない、Android は最大 4096・ASTC 6x6）を適用し、反射のキューブマップを焼き、Lighting / Env_ExhibitionRoom Prefab に `Environment` / `ExhibitionRoom` のバインディングを設定する。Env_ExhibitionRoom には `EnvironmentFadeGroup` を付け、部屋のすべての Renderer と、各マテリアルから作った透明マテリアルを登録する（URP Lit 以外のマテリアルはエラーにする）。FBX に埋め込まれたマテリアルは外部マテリアルと名前が重なることがあるため、透明マテリアルのファイル名にモデル名を付ける。反射と環境光だけを焼き直すときは `DNP Demo/Setup/Bake Environment Lighting` を使う。パノラマを回転・露出を反映して 512×256 の緯度経度画像に縮め（`Art/Environment/Reflections/`）、Cube（Glossy Reflection の畳み込み、面 128px）としてインポートする。同じ画像を SH に投影してプリセットに保存する。`SphericalHarmonicsL2.AddDirectionalLight` は独自の単位を持つため、一様な白い空の応答で割り、一様な放射輝度 L の空が L の環境光になるようにする（Unity の Skybox 環境光と一致することをテストで確かめている）。インポーターの緯度経度レイアウトは空のシェーダーと同じく中央が +Z で、空と反射を同じ向きから描いて比べるテストで確かめている。Env_Temple Prefab には大理石の床（半径 10m の円盤、`M_TempleFloor`、影を受ける）を置き、ルートに `TempleFloor` のバインディングを設定する。パノラマの床は無限遠にあり影も受けないため、像の足元にはこの床が要る。床の上面は、フェードアウト中の展示室の床（y = 0）と奥行きを争わないよう 1mm 下げる。神殿のパノラマ（`Art/Environment/Environment_Temple_Panorama.jpg`）は生成せず、ないときはエラーにする。共有シーンは編集しない。

影の品質はプリセットの `ShadowQualitySettings`（Override、メインライトのシャドウマップ解像度、影の距離、カスケード数）で上書きできる。URP では影の解像度を Light ごとには持たず（`Light.shadowResolution` は Built-In 用）、URP アセットの値で決まるため、プリセットのライト設定には解像度を持たせない。Basis は影品質の設定（Quest の既定は Very Low：256px・5m・1カスケード）を `SMModuleShadowQualityURP` で URP アセットに書き込むため、神殿だけ Override を有効にし（2048px・8m・1カスケード）、展示室は Basis の値のまま使う。`EnvironmentController` は他の離散値と同じく遷移の t ≥ 0.5 で（`ApplyInstant` と舞台リセットでは即座に）切り替え、Override が有効になる最初の1回にその時点の値を退避してから書き込み、Override のないプリセットへ切り替えたら退避した値に戻す。Override 中は `LateUpdate` で値を比べ、パフォーマンスモードや品質変更で Basis に書き換えられたら上書きし直し、そのとき Basis が書いた値を新たな戻し先にする。品質レベルの切り替えで URP アセット自体が替わったときは、元のアセットへ値を戻してから新しいアセットを上書きする。URP アセットはプロジェクトのアセットで、エディタの Play 中の変更が .asset に残るため、`OnDisable` / `OnDestroy` では必ず元の値に戻す。

シナリオ step 21 までは展示室を基準とし、step 22「結び」の先頭にある永続 `EnvironmentCue` が神殿へ切り替え、直後の `SetObjectActiveCue`（`TempleFloor`）が、シーンでは非表示の Env_Temple を表示する。後続ステップや途中参加では `ApplyInstant` で同じ状態を即時再構築し、舞台リセットでは展示室プリセットへ戻す。

### 2.7 タスク HUD

操作を待つステップの間、両方の端末で、手元に追従する小さなパネルにステップの内容を表示する。コードは `Scripts/Runtime/TaskHud/`、プレハブは `Prefabs/Scenario/TaskHud.prefab`（DemoSystems の `Scenario/TaskHud`）。

- 見出しは、担当プレイヤーには「TASK」、担当でないプレイヤーには「プレイヤーA が操作中」と出す。その下に、ステップのタスク文（`ScenarioStep.TaskText`）と、操作定義の部品の手順文（`InteractionPart.Instruction`）を順に並べる。済んだ手順に ✓、現在の手順に ▶、残りに ・ を付ける。ペンのメニューで選ぶモードの手順には「（範囲選択モード）」のようにモード名を添える。
- 手順の下に、実行中のツールが渡した状態の文（`InteractionRunner.Status`）を出す。今は音声指示の「音声入力中…」と認識結果で使う。この文は端末ごとで、相手には送らない。部品が変わると消える。
- 担当プレイヤーのペンのモードが現在の手順と違うときは、「メニューの「空間ペン」で「物体移動」を選んでください」と案内する。
- 相手の選択範囲、ストローク、掴んでいる部位の動きは空間にそのまま見えるので、2人とも同じ変化を見られる。
- 最後の手順が完了するとステップが進み、HUD はすぐに消える。
- 表示内容は `TaskHudContent`（純 C#。`TaskHudContentTests` で確かめる）が、`InteractionRunner` の実行中のステップ（`CurrentStep`）、部品番号、担当かどうか、ペンのモード、状態の文から作る。`TaskHudView` が `InteractionRunner.StateChanged` とペンのモードの変化を受けて描き直す。
- 位置は `HandFollower`（`Scripts/Runtime/Presentation/`）が決める。最後にペンを握った手の逆の手（`SpatialPenController.LastGrabHand` の逆。初期は左手）の IK 後の位置の少し上に置き、向きは常に目の方へ向ける。デスクトップと、その手のコントローラーが追跡されていないときは、視界の下のその手の側に置く。
- 操作を待つステップでは、部品が始まってから一定時間たっても完了しなければ、ヒントを両方の端末に表示する。
  - 設定は部品ごとの `InteractionPart.Hint`（`InteractionHint`）に持つ。待ち時間（`DelaySeconds`、初期値 20 秒。0 ならヒントなし）、HUD に出す文（`Text`）、光らせるゾーンのキー（`ZoneKeys`）。
  - `ZoneKeys` が空なら部品のゾーンを光らせる。範囲選択は対象ゾーン、ガイドの線は始点と終点のゾーン、部位の操作は掴むゾーン（目標の姿勢はゴーストが常に示している）。線画、音声指示、履歴はゾーンがないので文だけを出す。`ZoneKeys` のキーも `ScenarioSceneBindingTests` で確かめる。
  - `InteractionHintPresenter`（`Scripts/Runtime/Interaction/Hint/`、DemoSystems の `Scenario/Interaction/InteractionHint`）が、`InteractionRunner.CurrentSession` が変わるたびに計時をやり直す。時間は端末ごとに数え、通信はしない。役割が変わって部品がやり直しになったときも数え直す。ヒントは部品が終わるか、ステップが進むと消える。
  - ゾーンは `HintZoneView` が、形（球、カプセル、箱）の半透明の黄色で点滅させて描く（`Art/Interaction/Hint/HintZone.mat`）。毎フレームゾーンの今の姿勢で描くので、動かしている林檎にもついていく。非表示のゾーンは描かない。
  - 文は「ヒント：」を付けて、タスク HUD の最後の行（`TaskHudView._hintText`）に出す。ヒント文に新しい文字を使ったら、UI フォントの文字セットに加える（`UiFontTests` が検出する）。
  - 既存の DemoSystems と TaskHud プレハブには、メニュー「DNP Demo/Setup/Install Scenario Into DemoSystems Prefab」を再実行すると、足りないヒントの部品と HUD の行が追加される。

### 2.8 学者 NPC・ナレーター

- 学者A（考古学）と学者B（構造力学）は **VR 内の NPC** として実装する。台詞は事前に用意した音声（生声または合成音声。台詞ごとに1ファイル）で再生し、頭上に字幕を出す。音源は位置付き（3D）、口パクは Basis 同梱の uLipSync を流用する。
- 学者の見た目は VRoid の VRM を Variant（`Scholar_A_Archaeologist` / `Scholar_B_Engineer`）の子 `Avatar` に置く。待機アニメーション（`Art/Scholars/AC_ScholarIdle.controller`）で立ち、音源は口、字幕は頭の上に、モデルごとに合わせる。口パクは uLipSync の母音を顔の `Fcl_MTH_A`〜`O` に `uLipSyncBlendShape` でつなぐ。母音の判定は uLipSync 付属の `uLipSync-Profile-Sample` を使う。
- ナレーターは位置を持たない 2D 音声で、視界の下に字幕を出す。

### 2.9 効果音（SE）

コードは `Scripts/Runtime/Audio/`、データは `Data/SeCatalog.asset`。mp3 はリポジトリに含めない（README「効果音（SE）の配置」）。

```
SeEvent    … 効果音を鳴らす場面（生成、変形、選択確定、スナップ、音声入力の開始と終了、タスク表示、完了、失敗）。値はアセットに保存されるので変えない
SeCatalog (ScriptableObject) … 場面ごとのクリップと音量、全体のマスター音量（既定 0.3）。クリップが無い場面は無音
SePlayer   … 操作の効果音をこの端末だけで鳴らす（InteractionRunner から呼ぶ）。ステップが変わっても止まらないよう、シナリオの効果音とは別の AudioSource を持つ
SeHold     … 台詞の再生中に要求された効果音を保留し、台詞が終わったら鳴らす。保留するのは最新の1つだけで、2秒待っても台詞が続くときはその時点で鳴らす
SeDucking  … 台詞の再生中は効果音の音量を 0.3 倍に下げる（0.15 秒でフェード）。SePlayer と ScenarioStage の両方に掛ける
```

- 像の生成と変形の音は、シナリオの `SoundCue`（そのステップの最初の台詞の直後）が `ScenarioStage` の効果音のソースで鳴らす。
- 1回の操作で鳴る効果音は1つ。部品の完了音（最後の部品なら完了、それ以外は操作の音）を鳴らしたときは、次の部品のタスク表示の音を鳴らさない。ステップの最初の部品ではタスク表示の音を鳴らす。相手の端末も同じ規則で、操作した端末と同じ音を鳴らす（`PartSoundGate`）。
- 全体の音量は `SeCatalog` のマスター音量で変える。場面ごとの音量と `SoundCue` の音量は既定 1 で、個別に下げたいときだけ使う。

### 2.10 セットアップ用のメニュー

DemoSystems への組み込み（§2.2 の Install Scenario Into DemoSystems Prefab）のほかに、次のメニューがある。

| メニュー「DNP Demo/Setup/…」 | 役割 |
|---|---|
| Assign Voice Clips | 現在の音声セット（`Audio/Voice/` の番号付き wav）を、再生順にシナリオの `LineCue` へ割り当てる。台詞とファイルの数が合わないときは何も変えない |
| Install Sound Effects | `SeCatalog` を作成・更新し、シナリオに版の効果音の `SoundCue` を足し、DemoSystems に `SePlayer` を組み込む。mp3 を置いたあとに再実行すると、空のクリップを埋める |
| Reset Effect Materials | 選択範囲・ストローク・ゴースト・版の切り替えのマテリアルを、既定のシェーダーと値に戻す |
| Install Lobby Credits | ロビーパネルの役割選択画面に、音声と効果音のクレジットを追加・更新する |
